## 문제

Phase 10 에서 추론 축 8개를 기각했고, 이후 가림 축을 4번·identity 축을 2번 더 돌렸으나
**순증이 하나도 없었다.**

| 축 | 시도 | AFLW |
|---|---|---|
| 가림 (사각형 p=0.5) | | 5.085 → 5.173 ❌ |
| 가림 (사각형 p=0.2) | | 5.079 ⚠ 잡음 |
| 가림 (실제 물체 p=0.9) | `occ` | 5.120 ❌ |
| identity 일관성 | `idcons` | 형상 26% → 8% ❌ |
| identity + 붕괴방지 | `idcons_v` | 형상 13% ❌ |
| 데이터 배수 179→32 | `x32` | 5.197 ❌ |

⚠ **Phase 10 의 "x32 미판정" 기록은 낡았다.** 완주해서 3.839 / 5.197 로 기각됐다.
그 문서를 정정했다.

## 가설 A — 미학습 (`meta_paper_aug_synergy_e80`)

11개 런 중 **6개가 ep47~50 에서 최고**였다. 코사인 LR 이 바닥에 닿는 지점이고 곡선이
안 꺾인 것처럼 보였다. 논문은 epoch 수·LR 스케줄을 안 밝혔고(supplementary §C 는
배치·wd·momentum·k 만), 우리 50 은 v1 코드에서 온 추정치다. 같은 데이터·파라미터를
쓰는 SynergyNet 은 80 epoch(milestone 48/64)이다.

**미학습이라면 지금까지의 모든 비교가 덜 학습된 상태끼리의 비교다.**

### ❌ 결과 — 기각

| | AFLW2000-3D |
|---|---:|
| 50 epoch (대조군) | **3.657** |
| 80 epoch | 3.652 |
| 차이 | **−0.005** |

곡선을 보면 이유가 분명하다:

| ep | e80 | 50ep 대조군 |
|---:|---:|---:|
| 41 | 4.411 | 3.786 |
| 49 | 4.228 | **3.657** |
| 61 | **3.697** | — |
| 65~80 | 3.71~3.75 | — |

**ep61 에 3.697 에 닿은 뒤 20 epoch 동안 정체한다.** 코사인이 늘어나 중간 구간
(ep41~49)에서는 오히려 50ep 대조군보다 +0.5~0.6 나빴고 끝에서 겨우 따라잡았다.

> **"6개 런이 ep47~50 에서 최고"는 미학습 신호가 아니었다** — 코사인 LR 이 바닥에 닿아
> 자연히 최저가 되는 지점이다. 내가 그걸 거꾸로 읽었다.

## 가설 B — 백본 (진행 중)

### 왜 지금인가

지금까지 실패한 축은 전부 **손실·증강·표집**이었다. 남은 성격이 다른 축이 백본이다.

300W-LP 는 얼굴 3,837개를 179배로 부풀린 **합성 셋**이라 시각적 다양성이 없다.
**obj365 검출 사전학습은 그 부족분을 가중치로 들여오는 유일한 경로다.**

⚠ **백본 축은 사실상 미탐색이었다.** `mbv2` 한 번(b256 시절, 4.138)뿐이고,
**현재 최고 레시피(b128 + 증강 + 순환)에서 백본을 바꾼 적이 없다.**
사전학습 백본 3종은 구현만 되고 **0회 실행**이었다.

### 후보

| 백본 | Params | MACs | CPU 1T | 사전학습 |
|---|---:|---:|---:|---|
| `mobilenet_v1` (현재) | 3.27M | 177M | 5.70ms | 없음 |
| **`pierrotxv2_n`** | **1.27M** | 79M | **4.07ms** | **obj365** |
| **`yolo26_n`** | **1.37M** | 61M | **4.05ms** | **obj365** |

**파라미터가 절반 이하인데 CPU 는 30% 빠르다.**

가중치 로드 확인 (스모크):

```
[FA3D] 검출 사전학습 로드 pierrotxv2-n-accuracy.obj365-ep150.pt
       — 168 텐서 · missing 0 · unexpected 0
```

### 실험

현재 최고 레시피에 **백본만** 바꾼다.

1. `meta_paper_aug_synergy_pierrotx` — 완주
2. `meta_paper_aug_synergy_yolo26` — 진행 중

대조군 `meta_paper_aug_synergy` — AFLW2000-3D **3.657** · AFLW **5.085** · 형상 설명분산 **26%**.

### 판정 기준

- 주 — AFLW2000-3D 와 AFLW **동시에** 대조군 이하 (한쪽만 좋아진 사례가 반복됐다)
- 형상 — 설명분산 26% 아래로 떨어지면 안 된다 (`idcons` 가 NME 를 올리며 6% 로 붕괴시킨 전례)
- 속도 — 이기지 못해도 **동등한 정확도에 30% 빠르면** 그 자체로 의미가 있다

### 정확히 무엇을 바꿨나 — 대조군 대비 전체 diff

이 표가 다음 절(가설 C)의 근거이므로 빠짐없이 적는다.

| 항목 | 대조군 `mobilenet_v1` | `pierrotxv2_n` | `yolo26_n` |
|---|---|---|---|
| `model_name` | mobilenet_v1 | **pierrotxv2_n** | **yolo26_n** |
| `model_extra` | `{}` | **`{input_size:128, pretrained_det:True}`** | 동일 |
| 백본 파라미터 | 3.27M | **1.266M** (−61%) | **1.365M** (−58%) |
| 헤드 파라미터 | 0.204M | 0.102M | 0.102M |
| 특징 벡터 `feat_dim` | 1024 | **512** | **512** |
| 특징 추출 | 최종 stage avgpool | **P3+P4+P5 풀링 concat** | 동일 |
| 네트워크 입력 | 120 그대로 | **120 → 128 bilinear** | 동일 |
| 사전학습 | 없음 (스크래치) | obj365 (자체 ep150) | **obj365 오피셜 체크포인트** |

입력 리사이즈는 선택이 아니다 — 두 백본 모두 stride 32 라 입력이 32의 배수여야 하고,
`config.py:65` 가 이를 강제한다. GT 파라미터 좌표계는 120 크롭 기준 그대로 둔다
(`yolo_backbone.py:119`).

**학습 하이퍼파라미터는 한 글자도 안 바꿨다.**

| | 세 실험 공통 |
|---|---|
| `lr0` / `lrf` | 0.02 / 0.01 |
| `momentum` / `nesterov` | 0.9 / True |
| `warmup_epochs` | **1.0** |
| `weight_decay` / `wd_scope` | 5e-4 / `conv` |
| 백본·헤드 LR 분리 | **없음 — 둘 다 0.02** |
| 나머지 | epochs 50 · batch 128 · sgd · `meta_k` 100 |

### ❌ 결과 — `pierrotxv2_n` 기각

| | AFLW2000-3D | AFLW | 형상 설명분산 |
|---|---:|---:|---:|
| 대조군 `meta_paper_aug_synergy` | **3.657** | **5.085** | **26%** |
| `pierrotx` | 3.733 | 5.222 | 22% |
| 차이 | +0.076 | +0.137 | −4%p |

**세 기준 모두 미달.** 남은 건 속도(4.07ms, 30% 빠름)뿐이다.

그런데 곡선이 단순한 실패가 아니다:

| ep | 대조군 | `pierrotx` |
|---:|---:|---:|
| 1 | 15.678 | **6.208** |
| 25 | 4.332 | **4.145** |
| 49 | **3.657** | 3.793 |

**ep1 에 15.678 vs 6.208 — 사전학습은 확실히 작동한다.** 중반까지 앞서다가 끝에서만
역전당한다. 이 모양은 "백본이 나쁘다"가 아니라 **후반에 대조군이 계속 내려가는 동안
이쪽은 먼저 바닥을 친다**는 뜻이다. 용량 부족이거나 레시피 불일치다.

⚠ **두 원인이 분리돼 있지 않다.** 백본을 바꾸면서 파라미터도 3.27M → 1.27M 로 61%
줄었다. 위 표의 diff 전체가 한 번에 들어갔으므로 이 실험만으로는 못 가른다.

## 가설 C — 사전학습 백본에는 백본 전용 학습 파라미터가 필요하다

### 근거 1 — 코드가 지원하는데 아무도 안 쓴다

`pierrotfr/FA3D/engine.py:200` 은 파라미터 그룹별 LR 배수를 이미 지원한다.

```python
g["lr"] = lr * g.get("lr_mult", 1.0)
```

**저장소 어디에서도 `lr_mult` 를 설정하지 않는다.** `train_fa3d.py` 의 optimizer
빌더가 그 이유를 명시한다:

> *"pierrotfr/optim.py 는 사전학습 백본 + 새 헤드 구조를 전제로 LR 을 나누는데,
> 여기는 전체 스크래치라 그 분리가 의미가 없어 따로 만든다."*

이 주석은 **mobilenet_v1 을 위해 쓰였고, 사전학습 백본에는 성립하지 않는다.**
obj365 백본과 랜덤 초기화 헤드(`std=0.01` 정규분포)가 똑같이 lr 0.02 를 받고,
보호 구간은 warmup **1 epoch** 뿐이다.

### 근거 2 — 이 백본들을 실제로 쓰는 랩의 값이 다르다

`Pierrot_3D_Lab/train_pose.py` 와 `configs/args_pose.py` 는
같은 두 백본(`pierrotxv2_n` · `yolo26_n`)으로 자세 추정을 학습한다.

| | Pose Lab | 우리 FA3D |
|---|---|---|
| `lr0` | **0.01** (nbs=64 기준) | 0.02 |
| `momentum` | **0.937** | 0.9 |
| `warmup_epochs` | **3.0** | **1.0** |
| `weight_decay` | 5e-4 + **nbs 배치 보정** | 5e-4, 보정 없음 |
| `nbs` (기준 배치) | **64** | 개념 자체가 없음 |

`train_pose.py` 는 하이퍼파라미터가 **전역 배치 64 기준으로 튜닝됐다**고 명시하고,
실제 배치가 다르면 보정한다:

> *"전역배치 > nbs → accumulate=1. 대신 weight_decay 를 배치 비율만큼 키운다.
> 감쇠는 갱신 1 회당 걸리는데 배치가 크면 같은 데이터를 도는 동안 갱신 횟수가
> 줄어, 보정하지 않으면 총 감쇠량이 그만큼 작아진다(정규화가 조용히 약해진다)."*

**우리는 전역 배치 128 인데 보정이 없다.** 이 백본들이 정말 64 기준이라면
정규화가 절반으로 약해진 셈이고, 이는 "끝에서 역전당한다"는 관측과 방향이 맞는다.

### ⚠ 그대로 가져오면 안 되는 것

- `momentum` 0.937 — **논문이 밝힌 6개 중 하나(0.9)** 다. 바꾸면 논문 재현 범위를
  벗어난다. 백본 실험 한정으로만 정당하며 그렇게 표시해야 한다.
- `lr0` 0.01 — 우리 0.02 는 b128 에서 **실측으로 고른 값**이다(b256·lr0.04 대비
  −0.306). Pose Lab 값은 과제가 다르다(검출/자세 vs 3DMM 회귀).

### 실험 설계 — 논문 설정을 안 건드리는 두 축만

| 변경 | 값 | 왜 이것만인가 |
|---|---|---|
| `warmup_epochs` | 1 → **3** | Pose Lab 값. 사전학습 가중치를 랜덤 헤드의 초기 기울기에서 보호 |
| 백본 `lr_mult` | 1.0 → **0.1** | 전이학습 표준. `engine.py` 가 이미 지원 |

일부러 뺀 것도 적어 둔다 — **원칙은 "논문이 안 밝힌 것만 건드린다"** 이고, 이걸 깨면
격차가 줄어도 재현이라고 말할 수 없다.

| 뺀 후보 | 이유 |
|---|---|
| `lr0` 0.02 → 0.01 | **`lr_mult` 와 중복.** 백본 실효 LR 이 이미 0.002 로 Pose Lab 의 0.01 보다 5배 낮다 |
| `momentum` 0.9 → 0.937 | **논문이 명시한 6개 중 하나** |
| `wd` nbs 보정 (→1e-3) | 논문이 b128 에서 5e-4 를 **명시**했다. nbs=64 는 Pose Lab 의 튜닝 기준일 뿐 |

배선은 `train_fa3d.build_optimizer` 에서 `backbone.*` 을 따로 묶는 방식이다. 88개 텐서
전부가 그룹에 들어가고 백본 84개가 0.002, 헤드 4개(`fc_param`/`fc_lm`)가 0.02 를 받는다.
`lr_mult != 1.0` 인데 `backbone.*` 이 없으면 `SystemExit` — mobilenet_v1 에 실수로 걸면
조용히 무시되는 대신 즉시 멈춘다.

### ❌ 결과 — 가설 C 기각

| | AFLW2000-3D | AFLW2000-3D(re) | AFLW |
|---|---:|---:|---:|
| 대조군 mbv1 | **3.657** | 2.963 | **5.085** |
| `pierrotx` | 3.733 | 3.013 | 5.222 |
| `pierrotx_lr` | 3.860 | 3.228 | 5.358 |

**세 지표 전부 나빠졌다.** 자세 구간별로도 전 구간 열세이고 고각(60~90°)이 +0.218 로
가장 크다(4.718 → 4.936).

### 진단은 맞았고, 처방이 트레이드오프였다

| 구간 | `px_lr` − `px` | lr 승 |
|---|---:|---:|
| ep1–3 | +1.094 | 0/3 |
| ep4–10 | +0.765 | 2/7 |
| ep11–25 | +0.086 | 8/15 |
| **ep26–40** | **−0.217** | **12/15** ✅ |
| **ep41–50** | **+0.092** | **0/10** ❌ |

```
ep29   px 5.036  →  px_lr 3.955    -1.081   ← 붕괴 지점
ep30   px 4.545  →  px_lr 3.954    -0.591
```

**`pierrotx` 가 ep26~30 에 튀어 오르던 현상이 완전히 사라졌다.** "높은 LR 이 사전학습
백본을 무너뜨린다"는 진단은 참이었고 `lr_mult` 가 실제로 고쳤다.

그런데 최저점은 오히려 나빠졌다.

| 구간 | `px_lr` 최저 | `px` 최저 |
|---|---:|---:|
| ep11–25 | **3.936** | 4.145 |
| ep26–40 | 3.900 | **3.776** |
| ep41–50 | 3.860 | **3.733** |

ep25 에 3.936 으로 **더 일찍 좋은 곳에 도달하고 거기서 멈춘다.** ep33 에 3.900 을 찍은
뒤 남은 17 epoch 을 3.86~4.02 에서 맴돈다. 코사인이 바닥에 닿는 구간에서 백본 실효
LR 이 0.0002 수준까지 떨어져 **미세조정 자체가 불가능**해진다.

변동성도 줄지 않았다 — ep11~50 표준편차 `px_lr` 0.426 vs `px` 0.352. ep5 의 9.006,
ep13 의 5.775 같은 튐이 초·중반에 그대로 남는다.
**`lr_mult` 는 안정성을 준 게 아니라 특정 구간의 붕괴 하나만 막았다.**

> **붕괴를 막은 대가로 최종 수렴 여력을 잃었다.** 순손실 +0.127.

## 백본 축 종합 — ❌ 닫는다

| 런 | 백본 | 레시피 | AFLW2000-3D | AFLW |
|---|---|---|---:|---:|
| 대조군 | mobilenet_v1 3.27M | 기본 | **3.657** | **5.085** |
| `pierrotx` | pierrotxv2_n 1.27M | 기본 | 3.733 | 5.222 |
| `pierrotx_lr` | pierrotxv2_n 1.27M | warmup3 + lr_mult .1 | 3.860 | 5.358 |
| `yolo26` | yolo26_n 1.37M | 기본 | 3.783 | 5.246 |

**백본 2종 × 레시피 2종 = 4런 전부 미달.** 남은 이점은 속도(CPU 30% 빠름)뿐이다.

> ⚠ **정정 (2026-09-04, [Phase 12](Phase_12_잡음_기준선과_flip_TTA.md))** — 이후 대조군을
> seed 3 개로 돌려 잡음 폭을 쟀더니 **AFLW2000-3D 2σ ±0.106 · AFLW ±0.210** 이었다.
> 이 기준으로 위 표를 다시 읽으면 `pierrotx`(+0.076/+0.137)는 **판정 불가**,
> `yolo26`(+0.126/+0.161)은 **경계**이고, 확실히 나쁜 것은 `pierrotx_lr` 하나뿐이다.
> **"백본 축을 닫는다"는 단정은 근거가 약하다.** 다만 네 런이 모두 같은 방향(나쁨)이라는
> 점은 남는다 — 순수한 우연이라면 부호가 섞였을 것이다.

### 이 국면에서 두 번 반복한 판단 오류

`yolo26` 이 ep1~9 에서 `pierrotx` 를 평균 −0.375, 대조군을 −1.787 앞섰을 때
"백본 개체 차이가 실재한다"고 읽었다. **최종은 `pierrotx` 보다 나빴다.**

그리고 `pierrotx_lr` 이 ep31 시점에 중반 붕괴를 지운 것을 보고 "효과가 보인다"고 썼다.
**최종은 기존보다 +0.127 나빴다.**

> 사전학습 백본은 **초·중반에 앞서는 게 기본값**이다(ep1 에 6.208 vs 15.678). 그 구간의
> 우위는 최종 성능의 근거가 못 된다. 같은 오류를 한 국면 안에서 두 번 했다.

### 남은 해석 — 용량

붕괴를 고쳐도 최종이 안 좋아졌다는 것이, 한계가 레시피가 아니라 **파라미터
3.27M → 1.27M(−61%)** 쪽에 있다는 쪽을 강하게 가리킨다. 검증하려면 `s` 스케일 백본으로
용량을 맞춰 다시 재야 한다 — 그때는 속도 이점이 사라지므로, 이긴다 해도 배포 가치는
따로 판단해야 한다.

## `nesterov=False` — ❌ 기각, 다만 판정 불가에 가깝다

논문은 "SGD with momentum" 이라고만 쓰고 nesterov 여부를 안 밝힌다. 우리 `True` 는
선택이지 재현이 아니다.

| | AFLW2000-3D | AFLW |
|---|---:|---:|
| 대조군 (`nesterov=True`) | **3.657** | **5.085** |
| `nonest` | 3.705 | 5.155 |
| 차이 | +0.048 | +0.070 |

⚠ **+0.048 은 우리가 아는 효과 크기 범위(±0.05~0.09) 안이다.** 단일 seed 이므로
이 판정에는 근거가 없다 — `erase02`(+0.008)·`e80`(−0.005) 도 같은 처지다.

## ⚠ 정정 — "논문과 직접 비교" 의 범위 (2026-09-03)

이 문서를 포함해 여러 곳에서 "논문 설정 그대로" 라고 썼는데, 정확히는 이렇다.

```
논문 supplementary §C 와는  →  대조했다. 밝힌 6개 항목 전부 일치
오피셜 학습 코드와는        →  대조 불가 — 저장소에 학습 코드가 없다 (추론부만)
```

오피셜 `models/mobilenet_v1.py` 는 62-d 단일 헤드뿐이고 학습 루프·optimizer·손실이 없다.

LR 스케줄·초기화·표집**이며, `ratio` 는 (동치이므로) 후보가 아니다.
