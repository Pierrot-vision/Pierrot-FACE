# Phase 12 — 극단 pitch: 증강으로 안 되는 구간, HRFFA 는 **데이터로** 풀었다

기간 09-09 · 결과 **격차 원인 확정 · 생성 사양 확보 · 깊이 워핑은 ±40° 까지만**

## 문제

HRFFA 저장소의 극단 자세 예제(pitch +42~88°, roll 0~320°)에 두 모델을 나란히 돌렸더니
**우리 윤곽이 안쪽으로 말린다.** 우리 최고 아암(`refine_C_v7`)이 명확히 진다.

합성 pitch 로도 확인했다(WFLW test 40 장, 화면 안 점만):

| 카메라 pitch | 우리 | HRFFA | GT 화면밖 |
|---|--:|--:|--:|
| −25° | **4.61** | 5.80 | 5% |
| −40° | 6.87 | **6.02** | 26% |
| −55° | 15.49 | **8.53** | 56% |

**±25° 까지는 우리가 21% 앞서고, ±40° 부터 뒤집힌다.**

⚠ 지표 오류 하나를 먼저 잡았다 — 화면 밖 점을 포함해 평균내면 −55° 에서 93.88 vs 63.22 가
되는데, 그 구간은 GT 의 **56% 가 크롭 밖**이다. "보이지도 않는 점을 얼마나 그럴듯하게
외삽하나"를 재는 값이라 국소화 정확도와 섞으면 안 된다. 화면 안/밖을 나눠야 한다.

## 가설과 판정

| 가설 | 판정 |
|---|---|
| 학습 증강 범위가 좁다 | ⭕ **일부 원인** — `teacher_v4`(±40° 학습)가 같은 예제에서 눈에 띄게 낫다 |
| 크롭 규약이 달라서 | ❌ 비교 시 **HRFFA 크롭 패널을 양쪽에 같이** 먹였다 |
| 백본·용량 | ❌ 우리 309M vs 그들 308M |
| **극단 자세 실사 데이터가 없다** | ⭕⭕ **주원인** |

## ★ HRFFA 는 그 구간을 데이터로 배웠다 — 사양이 공개돼 있다

`src/hrffa/dataset/schema.py:66`:
```python
"selftrain_lookup",    # T2 見上げ特化生成画像(synthetic_lookup)への教師擬似ラベル
```

`configs/lookup_traindata_generation.yaml` 이 전체 사양이다.

- **생성**: OpenAI Batch API `gpt-image-2` (quality low · JPEG q92) · **3,000 장 요청**
- **학습 반영**: `selftrain_lookup` 2,846 장 + `selftrain_v2` 4,864 장 = **학습셋의 22%**
- **자세 구간 7 개** (`bin_counts: [600, 750, 600, 300, 300, 300, 150]`):

| 구간 | pitch | yaw | 장수 |
|---|---|---|--:|
| pitch_up_20_40 | +20~40° | ±4~22° | 600 |
| pitch_up_40_60 | +40~60° | ±4~22° | **750** |
| pitch_up_60_90 | +60~90° | ±4~22° | 600 |
| pitch_up_90_120 | **+90~120°**(뒤로 젖힘) | ±4~18° | 300 |
| camera_low_20_60 | +0~30° (카메라 −20~60°) | ±4~24° | 300 |
| combined_30_60 × yaw30_90 | +30~60° | ±30~90° | 300 |
| combined_60_90 × yaw30_60 | +60~90° | ±30~60° | 150 |

**각도를 숫자로 주지 않고 물리적 상황으로 강제한다** — 이것이 설계의 핵심이다:
> pitch_up_60_90: *치과 의자에서 검진 램프를 본다* · *이발소에서 턱 아래를 면도받는다*
> pitch_up_90_120: *물리치료 벤치 가장자리로 머리를 젖힌다* · *미용실 샴푸 의자*

거부 조건도 명시돼 있다 — *정면·수평 시선 사용 불가* · *턱 아래와 콧구멍이 보여야 함*.

**품질 게이트**: 머리 높이 25~50%(목표 36~42%) · 검출 점수 ≥0.25 · 뒤통수/중복 거부 ·
처음 **100 장으로 드리프트 검사**(구간 일치율 80% 미만이면 나머지 2,900 장 중단) ·
`qa/lookup_pose_qa.py` 자세 붕괴 감사.
**라벨은 교사 의사라벨**이고 TTA 편차 `max_std_norm 0.03` 초과 시 버린다.

## 우리가 시도한 것 — 깊이 인지 재투영

생성 API 없이 만들 수 있는지 봤다. `pierrotfr/FA2D/depthwarp.py`:
Depth Anything V2 → 3D 역투영 → 카메라 pitch 회전 → 재투영.
**랜드마크도 자기 깊이를 읽어 같은 변환을 받으므로 의사라벨이 아니라 정확한 GT** 다
(이 점은 HRFFA 의 생성+의사라벨보다 낫다).

구현 중 하나 배웠다: 픽셀 단위 forward warp 은 표본화 구멍이 **+30° 에서도 25% 이상**이라
쓸 수 없다. 성긴 격자(48×48) 정점만 3D 변환하고 `griddata` 로 역매핑하는 **메시 방식**으로
바꿔야 구멍이 없다. 약 0.3 초/장.

**결과: ±30~40° 까지만 쓸 만하다.**

| pitch | 결과 |
|---|---|
| +25 / +40 | 자연스럽다 |
| +55 | 얼굴은 버티나 상단이 찢어진다 |
| +70 | 표면이 무너진다 |

원인 둘:
1. **단안 깊이는 장면 전체를 잰다.** 배경이 얼굴과 다른 깊이라 크게 늘어나며 찢어진다.
2. **가려진 면은 만들 수 없다.** +70° 에서 보여야 할 턱 아래는 원본에 정보가 **아예 없다.**
   어떤 워핑으로도 못 만든다 — HRFFA 가 생성 모델을 쓴 이유가 이것이다.

## 결론

- **±40° 까지는 증강/워핑으로 가능하고, 그 너머는 새 화소가 필요하다.**
- 다음 판정은 큐의 `pitch40_v7` / `pitch55_v7`(현재 최고 설정 + 증강만 확대)이 한다.
  증강으로 충분하면 비싼 생성 파이프라인은 불필요하다.
- 생성으로 간다면 걸림돌은 API 가 아니라 **교사다.** 우리 교사는 +60~90° 를 본 적이 없어
  그 구간 의사라벨이 부정확하다. HRFFA 도 단계적으로 올렸을 것이다
  (±25 학습 → 조금 넓은 데이터 생성 → 재학습 → 더 넓게). **닭과 달걀 문제**다.
- 우리에게 유리한 점 하나: 깊이 워핑은 **정확한 GT** 를 준다. ±40° 구간은 의사라벨 없이
  데이터를 늘릴 수 있다.
