# Exp — FA2D 실험 기록

한 **국면(Phase)** = md 파일 하나. 국면은 "무엇이 문제인지 알아낸 순간"마다 끊는다.
(규약은 [FA3D/Exp](../../FA3D/Exp/README.md) 와 같다.)

파일명: `Phase_<번호>_<한줄요약>.md`

## 각 문서가 답해야 하는 것

| 절 | 질문 |
|---|---|
| **문제** | 무엇이 안 되고 있었나. 어떤 관측이 그걸 말해 주었나 |
| **가설** | 왜 그런가. 후보가 여럿이면 전부 적고, 어떻게 가를지도 적는다 |
| **실험** | 무엇을 어떤 순서로 돌렸나. 통제 변인은 무엇인가 |
| **결과** | 숫자. 가설이 맞았나 틀렸나 |
| **결론** | 다음 국면으로 무엇을 넘기나. 틀린 가설은 왜 틀렸나 |

**틀린 가설도 남긴다.** 지운 가설은 다음 사람이 다시 세운다.
**측정 오류도 남긴다.** FA2D 에서만 벌써 넷이 나왔다 — EMA 를 epoch 단위로 갱신해
val 이 학습과 따로 놀았고, `sources` 가 깊은 병합돼 단독 학습에 다른 소스가 딸려
왔고, 큐가 `best.pth` **존재**만 보고 덜 학습된 교사로 증류를 돌렸고,
`eval_n=512` 부분집합이 전체 test 보다 0.77 낙관적이었다.
**비교 실험은 상대 모델의 크롭 규약을 지켜야 한다** — Phase 13 에서 외부 모델에 우리
머리 크롭을 줬더니 Peppa 가 4.35 → 24~53 으로 무너졌다. 순위가 통째로 뒤집힌다.
**부위별 평균은 점수 가중을 써야 한다** — 단순평균은 3.9~5.1% 어긋난다.
**GT 에도 결함이 있다** — WFLW test 6.2% 에 중복 좌표가 있어 접선 분해가 무의미해진다.
**상대 모델은 네 가지를 맞춰야 잰다** — 헤드(68 vs 98) · 크롭(박스 출처·모양) ·
색 순서(BGR/RGB) · NME 좌표계. Phase 14 에서 넷 중 셋을 틀려 HRFFA 4.840 · 12.489,
Peppa 4.640 · 5.004 를 폐기했다. 규약을 맞추자 Peppa 공개값이 0.01 이내로 재현됐다.
**중단된 명령도 실행됐을 수 있다** — 거부된 호출의 큐가 살아 있어 같은 학습(`full_v11`)이
두 개 동시에 같은 run 폴더·로그를 썼다(메모리 2배·속도 1/3). 큐를 다시 띄우기 전에 `ps` 로 본다.
**설정값은 동작의 증거가 아니다** — `hard_mining: True` 가 설정에 있었지만 `update_weights`
호출이 없어 `full_v8`~`full_v11` 과 Phase 15 학생 아암 전부가 표본 가중 없이 학습됐다.
Phase 16 에서 연결했다. 켰다고 적기 전에 로그에서 갱신 줄을 확인할 것.
**학습 안 한 헤드로 평가하면 값이 무의미하다** — 300W 평가가 학습된 적 없는 ibug68 쿼리로
돌아 59~69 가 나왔다. Phase 15 에서 300W 를 학습에 넣으며 해소했다.
**판정 오류도 남긴다** — Phase 9 에서 Peppa 의 **미사용 파일**(`face_model.py`)을 읽고
"구조 가설 기각"이라 적었다가 Phase 10 에서 뒤집었다(실제 학습 경로는
`lib/core/base_trainer/model.py`). 진입점에서 역추적할 것.
또 두 점으로 적합한 절편(3.853)을 **관측된 한계처럼** 인용했다 — 외삽값이다.
또 DDP 에서 scheme 별 쿼리 grad 가 1/world_size 로 조용히 희석됐고(Phase 8),
경량 CNN 백본을 stride 16 에서 끊어 사전학습의 76~92% 를 버렸으며(Phase 6),
pose-stress 를 HRFFA(±25°)와 다른 범위(±55°)로 재고 같은 축인 양 비교했다(Phase 8).
