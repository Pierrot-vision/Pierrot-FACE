# Phase 10 — 기존 아암의 한계와 고해상도 국소화 가설

기간 09-07 ~ 09-08 · 결과 **분석 정정 · 국소 보정 A/B/C 구현 및 동작 검증 완료, 정확도 효과 미측정**

> 정정: 초안은 특징 격자를 출력 좌표 격자로 해석하고, 두 해상도에서 적합한
> 절편 3.853을 stride 14의 정밀도 하한으로 단정했다. 이 결론은 철회한다.
> 실험 수치는 남기되 관측, 인과 추론, 다음 제안을 구분한다.

## 문제

`teacher_v3`(448 · pad .15)의 WFLW test 2,500장 io-NME는 **4.120**이다.
Peppa Teacher@256 **3.95**보다 0.170 NME, 상대 **4.3%** 높다.
Peppa Student@256은 **4.35 / 3.25M**, Teacher@256은 **3.95 / 11.53M**이다.
교사의 정확도와 학생의 크기를 한 모델의 성능처럼 결합하면 안 된다.

우리 교사는 약 309M이다. 초안의 **386 GFLOPs는 336 입력용 수치가
`teacher_` 접두사 매칭으로 v3에도 붙은 비교표 오류**다. 448 입력 비용은 재측정 전까지
미확인으로 둔다. 기존 문서의 687도 이 검토에서는 실측 근거를 확인하지 못했다.

HRFFA 공개 WFLW 수치는 test를 학습에 포함한 적합도이므로 일반화 순위의 근거가 아니다.
Peppa·D-ViT와도 크롭·증강·학습 조건이 달라 수치 차이가 곧 구조의 효과는 아니다.

## 코드에서 확인한 구조 차이

Peppa의 `lib/core/base_trainer/net_work.py`는 `lib/core/base_trainer/model.py`의
`Net, COTRAIN`을 사용한다. Phase 9에서 읽었던 `lib/core/model/face_model.py`는
이 학습 경로가 아니다.

```python
decx8 = self.upsampler1(encx16, encx8)
decx4 = self.upsampler2(decx8, encx4)
hm = self.hm(decx4)  # 히트맵 98 + x 오프셋 98 + y 오프셋 98
```

학생은 MobileNetV3, 교사는 HRNet-W18이다. ASPP와 **실제 stride 8·4 특징의
skip 연결**을 이용한다. 히트맵은 AWing, 오프셋은 히트맵 가중 Wing loss로 감독한다.
따라서 Phase 9의 **“구조 가설 기각”은 잘못됐다.**

| 모델 | 좌표 출력 | 공간 업샘플 | 읽는 공간 표현 | 간격 / 눈사이 거리 |
|---|---|---|---|--:|
| Peppa@256 | 히트맵 + 오프셋 | ASPP + skip 업샘플 | 64×64 출력 히트맵 | 약 3.5% |
| HRFFA vitl-320 | 쿼리의 연속 좌표 회귀 | 없음 | 20×20 특징 | 초안 18.6%, 크롭 측정 근거 재확인 필요 |
| 우리 v3@448 | 쿼리의 연속 좌표 회귀 | 없음 | 32×32 특징 | 약 13.8% |

우리와 HRFFA에도 **Transformer 쿼리 디코더는 있다.** 없는 것은 공간 업샘플 디코더다.
우리 `coord_head`는 연속 좌표를 출력하며 패치 중심으로 양자화하지 않는다.
패치 채널에 내부 위치 정보가 남을 수 있으므로 stride 14가 좌표 오차 하한은 아니다.
3.5%와 13.8%는 공간 샘플 간격 비교이며 4배의 좌표 오차를 의미하지 않는다.

## 철회하는 원인 분석

1. **“stride 14 때문에 3.853 아래로 못 간다”**: 두 점에 맞춘
   `NME = 27.2 / 눈사이px + 3.853`의 절편은 외삽값이다. 같은 크롭에서 입력 R,
   눈사이 비율 r이면 상대 패치 간격은 `14/(rR)`로 R 증가에 따라 줄어든다.
   고정 픽셀 오차는 역해상도 항에 해당하며 상수항의 원인을 특정하지 않는다.
2. **“해상도는 격자를 안 건드렸다”**: 336→448에서 특징 격자는 24×24→32×32로
   증가했다. NME **4.209→4.120은 약 2.11% 개선**이며 1%가 아니다.
3. **“히트맵은 반드시 회귀보다 정밀하다”**: 직접 공간 감독과 고해상도 특징은
   유력한 이점이지만 현재 모델의 원인임을 확인하려면 통제 실험이 필요하다.
4. **“쿼리 유지로 360° 성능도 보존된다”**: 구조를 바꾼 뒤 회전 성능을 재측정해야 한다.
   히트맵도 회전 증강과 다중 규약을 사용할 수 있고, 쿼리 기반 공유 히트맵 헤드도 가능하다.
5. **“히트맵은 가시성 0의 좌표를 못 낸다”**: 크롭 내부 히트맵만으로 화면 밖 좌표를
   다루기 어렵다는 제약이다. 기존 회귀와 병행할 수 있다. 가려졌지만 화면 안에 있는
   점과 화면 밖 점은 구분한다.
6. **“HRFFA도 알고 누출로 가렸다”**: stride assertion은 구현의 지원 범위다.
   저자의 인식·의도나 누출이 특정 구조 약점을 상쇄했다는 인과를 증명하지 않는다.

## 구현 — 고해상도 국소 보정 추가 (동작 검증 완료·정확도 효과 미측정)

**가설:** 마지막 패치 특징만으로 좌표를 읽는 경로에 입력의 세부 특징을 공급하면,
머리 크롭·360° 증강을 유지한 채 정밀도를 높일 수 있다.

- 기존 DINOv2·쿼리 디코더·좌표/가시성/자세 헤드는 유지한다.
- 입력의 얕은 CNN에서 stride 4 특징(448 입력에서 112×112)을 얻고,
  채널을 줄여 업샘플한 DINO 특징과 결합한다. 단순 보간만으로 새로운 관측 정보가
  생기지는 않으므로 입력 분기의 기여를 분리해 평가한다.
- 초기 좌표 주변을 `grid_sample`로 읽고 해당 쿼리 토큰과 결합해 좌표 보정량을 예측한다.
  전체 112×112에 cross-attention하면 memory 토큰이 **12.25배** 늘어나므로
  첫 구현은 국소 추출을 사용한다.
- 마지막 보정층을 0으로 초기화해 추가 직후 기존 좌표를 재현한다. 초기 좌표에도
  손실을 유지한다. 첫 버전은 화면 밖 초기 좌표의 보정을 건너뛰고 기존 회귀를 쓴다.
  초기 위치가 크게 틀리면 국소 영역을 놓칠 수 있다는 한계도 평가한다.

구현 파일은 [refine.py](../../../pierrotfr/FA2D/models/refine.py)와
[decoder.py](../../../pierrotfr/FA2D/models/decoder.py)다. 기본 `refine=False`에서는
기존 출력 키와 체크포인트 구조를 유지한다. 보정이 켜지면 `coarse_points`를 추가하고,
기존 소비자가 읽는 `points`에는 최종 보정 좌표를 반환한다.

- **메모리:** DINO 1024채널을 저해상도에서 128채널로 투영한 뒤 112×112로 확대한다.
  C는 입력을 두 단계 평균 풀링하는 얕은 CNN의 64채널 특징을 결합한다.
  7×7 영역을 점별로 읽고 쿼리 토큰과 결합하는 MLP는 규약 간 공유한다.
- **좌표 정합:** GT의 좌표는 OpenCV 픽셀 중심을 입력 변 길이로 나눈 값이다.
  CNN 셀 중심을 원본 `4*i+1.5`로 맞추고, `align_corners=False` 샘플링에서는
  `grid_x = 2*x_norm - 1 + 1/W`를 사용한다. 격자 계산·샘플링은 FP32다.
  마지막 좌표 합도 FP32로 계산해 작은 보정량이 BF16 덧셈에서 사라지지 않게 한다.
- **초기 좌표 감독:** B/C는 기존 최종 좌표 손실 `w_coord=10`에 초기 좌표 손실
  `w_coarse=10`을 더한다. 샘플링 중심은 detach하지만 초기 좌표는 자체 손실과
  최종 좌표 합을 통해 학습된다. A는 기존 손실만 사용한다.
- **화면 밖:** 초기 좌표가 두 축 모두 `[0,1)`일 때만 보정을 적용한다.
  가려졌지만 화면 안인 점은 제외하지 않는다. 초기 좌표가 화면 밖이면 그대로 반환한다.
- **학습 연결:** GT 학습, 독립 평가, 증류 모델 구성에 refine 설정을 전달한다.
  새 모듈은 기존 optimizer의 헤드 학습률을 쓰며 기본 백본 배율 0.1은 적용하지 않는다.
  미사용 설정이었던 `refine_lr_mult`는 제거했다.

| 아암 | 변경 | 구분할 효과 |
|---|---|---|
| A | 기존 v3에서 추가 학습 | 추가 학습 자체의 효과 |
| B | DINO 특징만 이용한 국소 보정 | 보정 헤드·특징 재구성 효과 |
| C | B + 입력의 stride 4 CNN 특징 | 실제 고해상도 세부 정보 효과 |
| D (후속) | C + 국소 히트맵·오프셋 감독 | 직접 공간 감독 효과 |

### 초기화 오류 수정 및 실행

작업 트리의 초안은 100 epoch 학습한 `latest.pth`를 `resume`으로 읽으면서
새 아암을 30 epoch으로 설정했다. A는 학습 루프가 건너뛰어질 수 있고,
B/C는 추가 파라미터 때문에 strict 로딩이나 optimizer 복원에서 실패할 수 있었다.

이를 **`init_from`과 `resume` 분리**로 수정했다.
[checkpoint.py](../../../pierrotfr/FA2D/checkpoint.py)는 `best.pth`의 EMA를 우선 사용해
가중치만 로드한다(EMA가 없으면 model). optimizer·epoch·history·best는 새로 시작한다.
기존 키의 누락·예상 밖 키·shape 불일치를 검사하고, 신규 `refine.*` 키만 생략 가능하다.
부분적으로 손상된 보정 체크포인트도 거부한다. 파일이 없으면 처음부터 학습하지 않고 실패한다.
`init_from`과 `resume`의 동시 지정은 금지한다.

세 프리셋은 `configs.paths.work_dir`가 해석한 같은 v3 `best.pth`에서 시작한다.
동일 전역 배치 48, 30 추가 epoch, LR 5e-5, backbone 배율 .1, warmup 1 epoch,
cosine 일정으로 **처음부터 전체를 함께 미세조정**한다. 보정 분기만 동결 해제하는
별도 준비 단계는 이번 아암에 넣지 않았다.

저장소 루트에서 다음 명령을 각각 실행한다. 실행 결과는 각 프리셋의 별도 디렉터리에 저장된다.
아래 명령은 실행 방법이며, 이번 코드 수정에서 전체 학습을 시작하지는 않았다.

```bash
FA2D_PRESET=refine_A accelerate launch --num_processes 4 train_fa2d.py
FA2D_PRESET=refine_B accelerate launch --num_processes 4 train_fa2d.py
FA2D_PRESET=refine_C accelerate launch --num_processes 4 train_fa2d.py
```

기본 체크포인트 루트 기준 C의 학습 후 평가 예시다. 루트를 변경했으면 `--ckpt`와
`--out`도 해당 경로로 변경한다. A/B도 같은 옵션으로 평가한다.

```bash
python eval/FA2D/evaluate.py --preset refine_C \
  --ckpt runs/fa2d/refine_C_pointquery_dinov2-l14-reg/best.pth \
  --n 2500 --pose-stress 800 --jitter-n 100 \
  --out runs/fa2d/refine_C_pointquery_dinov2-l14-reg/eval_full.json
```

중단된 **동일 아암**을 재개할 때는 해당 프리셋의 `init_from=''`로 바꾸고
`resume`에 그 아암의 `latest.pth`를 지정한다. 완료된 v3를 `resume`으로 지정하지 않는다.

동일 초기 체크포인트·데이터·크롭·증강·소스별 노출량·추가 학습 스텝을 통제한다.
NME·FR10뿐 아니라 회전·pitch/yaw·화면 밖 좌표·추론 비용을 평가한다.
개선 후보는 개발 검증셋과 반복 seed로 확인한다. WFLW test에 반복해서 맞추면
학습에 직접 넣지 않아도 모델 선택 편향이 생기므로 최종 평가와 아암 선택을 분리한다.

현재 프리셋은 기존 학습 엔진과 같은 WFLW test 부분집합으로 checkpoint를 선택한다.
별도 개발 검증셋 분리는 아직 구현하지 않았다. 또한 기존 `LandmarkDataset`은 학습 증강에
`default_rng(None)`을 사용하므로 같은 cfg.seed가 동일 증강 샘플열을 보장하지 않는다.
현재 A/B/C는 동일한 설정·노출량의 비교이며 완전히 동일한 난수열의 비교는 아니다.

### 동작 검증 결과 (09-08)

- FA2D 기존/신규 테스트 **65개 통과**, 이후 추가한 학습 진입점 통합 테스트 **1개 통과**.
  경량 테스트 백본으로 실제 학습 엔진·EMA·평가·저장을 실행해 epoch 99 원본에서
  새 epoch 0·1이 수행되는 것을 확인했다. 원본 optimizer는 복원하지 않는다.
- B/C의 초기 출력 동일성, 다중 규약, strict 체크포인트 roundtrip, 손상된 초기화 거부,
  픽셀 중심·서브픽셀 샘플링, 화면 밖 게이팅, 초기/최종 좌표 손실과 분기 gradient를 검증했다.
- **실제 분기 크기** `image=448`, `patch=1024×32×32`, 98점, 256차원 쿼리로
  CPU BF16 순전파·역전파 통과. 추가 파라미터는 **B 1,885,442 / C 1,950,274**다.
- 이 환경에서는 `torch.cuda.is_available()`이 False다. GPU/DDP 전체 학습,
  v3 실가중치로 전체 데이터 평가, ONNX export, NME 개선은 아직 검증하지 않았다.
  기존 SciPy/NumPy 버전 경고 1종이 있었으며 테스트 실패는 없었다.

## 결론

기존 아암으로 Peppa Teacher의 NME를 넘지 못한 것은 관측 사실이다. 그러나
레버 전체의 소진, stride로 인한 정밀도 바닥, 단일 원인의 발견은 입증되지 않았다.
**확정된 오류는 Peppa 모델 경로 오독과 과도한 인과 해석이며, 다음 실험 대상은
고해상도 국소 특징과 공간 감독의 기여다.**

운영 기록: 초안 작성 당시 `teacher_v7`의 큐 누락 후 재실행을 기록했다.
