# Phase 1 — 5개 저장소 조사: 왜 HRFFA 기반인가

기간 08-31 · 결과 **극단 자세를 하는 건 HRFFA 뿐** · Peppa 는 구조적으로 불가

## 문제

2D 정렬 저장소 5개를 받았다. 어느 것을 기반으로 학습 코드를 짤 것인가.

## 가설

"성능이 제일 좋은 것"이 기준일 것이다 → **틀렸다.** 저장소마다 **푸는 문제가 달라서**
성능 비교 자체가 성립하지 않았다.

## 실험

각 저장소의 코드를 읽고 학습 코드 유무·좌표 디코딩·증강 범위·검출기를 확인했다.

| 저장소 | 학습 코드 | 좌표 디코딩 | roll | 검출 |
|---|---|---|---|---|
| **HRFFA** | **전체** (교사·증류·export·QA) | 점 쿼리 디코더 | **360°** | head |
| Peppa_Pig | 있음 (3.2k줄) | 히트맵(AWing)+offset | ±30° | face |
| face-alignment (FAN) | **없음** | 순수 히트맵 | 없음 | face |
| uniface | **없음** | 히트맵+offset+이웃회귀 | 없음 | face |
| mobilenet-v2 | 부분(Caffe, 가중치 없음) | FC 직접 회귀 | 없음 | face |

**5개 중 학습 코드가 있는 건 둘뿐**이었다.

## 결과

Peppa 가 극단 자세를 못 하는 것은 **세 겹이 전부 정면을 전제**하기 때문이다.

| 층 | 확인한 것 |
|---|---|
| 검출 | `yolov5n-0.5` = **얼굴** 검출기 → 고개 들면 bbox 자체가 안 잡힘 |
| 증강 | `uniform(-30, 30)` (`dataietr.py:289`) → 90°·180° 를 본 적 없음 |
| 데이터 | WFLW 단독, `extra_data=False` → 정수리·턱밑 시점 없음 |

반대로 HRFFA 는 **"그다음"이 전혀 없었다.** grep 결과 스무딩 0건, 추적 0건,
상태 분류 0건, 자세는 export 계약에서 제외("필요하면 PnP 를 쓰라").

성능 비교는 결론이 안 났다. 조건이 셋이나 어긋난다 — HRFFA 는 테스트 split 을
**전부 학습에 넣었고**(자기 표가 벤치마크가 아니라고 README 에 명시), Peppa 는
`Flops(G)` 단위가 불명이고, crop 규약이 head vs face 로 다르다.

## 결론

- **뼈대는 HRFFA 가 유일한 선택.** 목표가 극단 자세면 대안이 없다.
- **Peppa 에서 가져올 것은 알고리즘이 아니라 실사용 마감** — 스무딩·추적·상태 분류.
- ⚠ 초기에 "계산량을 맞추면 Peppa 가 낫다"고 판단했다가 **철회했다.** 파라미터가
  2배(3.25M vs 1.6M)인 것을 통제하지 않은 비교였다. 같은 규모에서는 HRFFA 가 이긴다.
- 남은 질문: HRFFA 의 커버리지와 Peppa 의 마감을 **어떻게** 합칠 것인가 → Phase 2
