# 극단 옆모습 GT·키포인트 정밀 감사

2026-09-10. `refine_C_v7`의 `best.pth` EMA와 기존 HRFFA/Peppa ONNX로
`three_way_profile.jpg`의 6장을 재추론했다. 세 모델의 18개 NME가 소수 둘째 자리까지
원 그림과 일치했다. 원 비교 그림과 기존 평가 코드는 수정하지 않았다.

## 판정

**GT 선을 따라 점이 밀리는 현상은 실제로 있다. 다만 전체 오차가 그것으로 설명되지는 않는다.**
원본 GT에는 여러 인덱스를 한 좌표에 겹쳐 표시한 사례도 있다. 이 때문에 점만 표시하면
키포인트별 차이가 숨겨진다. 이것이 주석 오류인지 의도된 가림 처리인지는 이 데이터만으로 확정할 수 없다.

### 1. 98점 그대로 분석해도 턱선의 접선 방향 오차가 크다

우리 모델의 원래 WFLW 98점 중 턱선 33점을 분석했다. 같은 번호 GT까지의 거리와,
GT 턱선의 선분까지의 최단 거리를 구분했다. 아래 거리는 동일한 448 입력 좌표계 px다.
접선 비중은 GT 국소 접선으로 투영한 오차 제곱합 / 전체 오차 제곱합이다.

|표본|같은 번호 점까지|GT 선까지|접선 방향 비중|
|---|---:|---:|---:|
|1|3.43|2.74|25.3%|
|2|7.80|4.42|42.6%|
|3|5.67|3.14|54.7%|
|4|8.01|3.68|83.3%|
|5|8.63|3.22|87.0%|
|6|14.02|9.64|42.9%|

4·5번은 선을 따라 위치가 밀리는 성분이 특히 크다. 6번은 선 자체와 떨어진 오차도 크다.
6번 턱선 시작점 WFLW 0번의 오차는 45.37px이고 1·2·3번도 41.55/39.07/35.47px다.
단순히 반 픽셀 보정으로 해결될 크기가 아니다. 1번의 최대 오차는 턱보다 눈썹
33~35번에 있으며, 34번은 18.47px다. 인덱스는 모두 0부터 센다.

선분 거리는 점의 의미·간격·순서를 완전히 평가하지 못하며, 같은 선에 점이 몰려도 작아질 수 있다.
따라서 NME를 대체하는 성능 지표가 아니라 원인 분해용이다. JSON에는 역방향 거리도 포함한
대칭 거리도 보관했다. 중복 GT로 접선이 정의되지 않는 점은 접선 통계에서 제외한다.

### 2. GT 자체의 중복 좌표

원본 annotation에서 확인한 정확히 같은 좌표의 인덱스 그룹:

- 1번: 코 57/58/59.
- 3번: 눈썹 **42~50의 9점 전체**; 코 57/58/59; 안쪽 입술 89/95 및 90~94.
- 4번: 코 57/58/59; 바깥 입술 79/80; 안쪽 입술 90/91/92.
- 5번: 안쪽 입술 90/91/92.
- 6번: 눈썹 **42~50의 9점 전체**; 눈 68/69/70/74/75 및 71/73.
- 2번에는 정확한 중복이 없다.

WFLW test 2,500장 전체의 원본 좌표를 검사하면 **155장(6.2%)**에 중복점이 있고,
**10장(0.4%)**은 한쪽 눈썹 9점 전체가 겹친다. 원본 파싱은 196개 숫자를 그대로 98×2로
읽는다. 따라서 크롭이나 98→68 축약 때문에 새로 생긴 중복이 아니다.

`read_wflw()`는 모든 점의 visibility를 -1(불명)로 읽으며 기존 `nme68()`은 크롭 안의
GT를 모두 평가한다. 가려져 겹친 점도 각각 계산된다. 보이는 실루엣이 자연스럽다는
판단과 주석의 인덱스별 위치를 재현한다는 판단은 구분해야 한다.

### 3. 우리와 HRFFA 비교

우리·HRFFA 예측을 동일한 크롭 좌표계로 옮겨 68점의 각 부위 내부에서만 선분 거리를 쟀다.
눈·입은 닫힌 선, 턱·눈썹·콧대·코 밑은 각각 분리했다. 얼굴 전체 선을 섞어 최근접점을 찾지 않았다.
아래는 이미지마다 눈 바깥꼬리 사이 거리로 정규화한 %를 표본 평균한 값이다.

|범위|우리 점 NME|HRFFA 점 NME|우리 선 거리|HRFFA 선 거리|
|---|---:|---:|---:|---:|
|1~5번|9.12|14.98|5.43|8.46|
|1~6번|10.50|14.95|6.44|8.47|

이 표본에서는 전체 선 형상도 우리가 더 가깝다. 하지만 6장을 합친 턱 부위만 보면
68점 선 거리는 우리 9.56, HRFFA 7.88로 HRFFA가 더 작다. 모든 부위에 오류가 없다는
주장은 성립하지 않는다. 동일한 68점 수를 쓰더라도 WFLW에서 고른 눈썹 위쪽 점과
native iBUG 눈썹 점의 세부 위치 규약이 동일하다는 것은 별도의 검증이 필요하다.
우리 98점에서 이미 관찰된 턱선 밀림은 이 축약만으로 설명할 수 없다.

### 4. 좌표계 감사 및 비교 코드의 별도 문제

- 우리 이미지와 GT는 같은 3×3 변환을 사용한다. 6장의 GT 왕복 변환 최대 오차는
  약 1.14e-13px. 전역 평행이동을 빼도 98점 NME는 1번 10.96→11.08,
  3번 9.45→9.45, 6번 18.52→18.73이다. 일괄적인 xy 오프셋이 주원인이라는 증거는 없다.
- 현재 `LocalRefine.sample_local()`에는 `align_corners=False`에 맞춘 반 픽셀 보정이 있다.
  이번 감사는 저장된 모델 예측을 분석한 것이며 학습 전체의 기하 정확성을 증명하는 것은 아니다.
- 표본 선정 기준 자체가 눈 사이 거리 / 얼굴 폭이 작은 순서다. 6장의 비율은 0.203~0.278이고,
  눈 사이 거리는 448 입력에서 35.41~59.76px다. 1번에서는 1px가 NME 2.82%p에 해당한다.
  작은 분모 때문에 육안상 작은 차이도 높은 NME가 된다.
- `peppa_crop()`은 실제 잘라낸 변 길이에는 `int(w)`를 쓰지만 GT에는 실수 `w`를 쓴다.
  `cv2.resize`의 픽셀 중심도 GT 계산에 반영하지 않는다. 이미지 입력을 고정하고 GT만 정확한
  resize 좌표로 계산하면 최대 좌표 차이는 0.70~2.73px다. Peppa NME는 표본 순서대로
  **10.06 / 14.53 / 12.00 / 10.02 / 11.30 / 107.10**으로 바뀐다.
  이는 우리/HRFFA의 차이를 설명하지 않는다. 기존 함수는 재현을 위해 그대로 두었다.
- `compare_three_regions.py`의 ‘전체’는 부위별 평균 5개의 단순 평균이다. 실제 68점 평균에는
  윤곽17/눈썹10/코9/눈12/입20의 가중치가 필요하다. Phase 13의 3.64 등을 공식 NME와
  직접 비교하거나, 98점과의 차이를 전부 윤곽 비중으로 설명하는 결론은 근거가 부족하다.
