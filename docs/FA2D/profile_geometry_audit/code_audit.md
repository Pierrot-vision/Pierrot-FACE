# 코드 감사: flip 편향 진단의 1픽셀 오류

2026-09-10. 결론: **실제 코드 오류를 재현하고 수정했다. 다만 TTA가 없는 기존 모델의
접선 오차 원인을 이 오류로 설명할 수는 없다.**

## 확정된 오류와 잘못된 원인 배제

- 학습 `geometric.flip_matrix()`는 `x' = W - 1 - x`.
- `LandmarkDataset._frame()`은 OpenCV 픽셀 중심 좌표를 `W`로 나눈다.
- 기존 `engine.predict_flip_tta()`는 정규화 좌표를 `1 - x`로 복원했다.
- 앞서 dx -0.690 / +0.394를 출력한 scratchpad의 `bias.py:36`도 같은 잘못된 식을 쓴다.
  즉 보고된 숫자에 직접 연결되는 오류다.

올바른 식은 `(W - 1) / W - x`다. 기존 식은 반전 결과에 +1px, 원본과의 평균에
+0.5px를 더한다. 따라서 원래 보고값에서 상수를 빼면 다음과 같다.

|400장 보고값|기존 복원|올바른 복원|
|---|---:|---:|
|원본 평균 dx|-0.690px|-0.690px|
|반전 후 원좌표계 평균 dx|+0.394px|약 -0.606px|
|TTA 평균 dx|-0.148px|약 -0.648px|

오른쪽은 **재추론 측정치가 아니라 기존 반올림 보고값에 대한 정확한 좌표식 보정**이다.
NME는 벡터 거리의 평균이므로 보고된 NME에 상수를 빼 재계산할 수 없다.
이전 TTA NME 3.218은 잘못 복원한 좌표로 산출된 값이다. 우연히 오른쪽으로 이동시키는
효과가 왼쪽 잔차를 일부 상쇄했을 가능성이 있으며, 수정 후 NME는 재평가가 필요하다.

**부호가 뒤집혔다는 근거는 사라진다.** 그렇다고 부호가 같다는 사실만으로 원래 편향이
반드시 파이프라인 버그라고 확정할 수도 없다. GT/데이터 조건 및 모델의 오차를 추가로
분리해야 한다. 기존 `bias.py`의 두 가지 원인으로만 가르는 설명은 충분하지 않다.

## 재현과 수정

`tests/FA2D/test_flip_coordinates.py`는 학습의 `apply_geometric()`으로 반전 GT를
만들고 이미지가 `cv2.flip()`과 일치하는지 먼저 검사한다. 원본·반전 양쪽 GT를 완벽하게
예측하는 가상 모델을 TTA에 넣으면 출력이 원래 GT와 같아야 한다.

수정 전 3규약 × 2해상도 = 6개 테스트 모두 x축 +0.5px 오차로 실패했다.
`engine.predict_flip_tta()`의 복원식을 `(W - 1) / W - x`로 수정했다.
학습·실행 중인 프로세스·체크포인트는 변경하지 않았다.

수정 후 `test_flip_coordinates.py`, `test_refine.py`, `test_fa2d.py`의 **73개 테스트 통과**.
이 검증은 좌표 계약과 기존 동작 회귀 검사이며 실제 데이터의 수정 후 NME 측정은 아니다.

## 나머지 점검 범위

- 학습 이미지/랜드마크: 같은 사영변환 적용.
- 학습 정규화와 평가 복원: `/W`와 `*W`로 일치.
- 반전 치환: 학습 FLIP_MAPPING과 TTA permutation 일치(세 규약 회귀 테스트).
- 현재 LocalRefine: 이미지 픽셀 중심을 반영한 sampling 보정과 FP32 최종 덧셈 존재.
- 기존 비교는 TTA 없이 호출하므로 이번 수정으로 `three_way_profile.jpg`의 기존 18개
  수치나 그 모델 자체의 점 배치가 바뀌지는 않는다.

## 신규 접선 손실의 별도 구현 주의점

이들은 `refine_C_v7`의 기존 오차 원인이 아니다. 신규 실험을 해석할 때의 문제다.

1. `tangential_coord_loss()`는 접선 **잔차**를 mult배 만든 뒤 xy Smooth L1에 넣는다.
   따라서 손실을 단순히 mult배 하는 것과 다르다. beta 안의 순수 접선 잔차 .001,
   mult=2 사례에서 손실 비율은 실제로 **4.0**이다. 또 xy Smooth L1은 전 구간에서
   회전 불변이 아니므로, 접선/법선 축에서 각각 계산한 손실의 가중합과도 다르다.
2. `tangential_weight_map()`은 모든 그룹을 열린 선처럼 처리한다. 닫힌 눈·입술의
   첫/마지막 점에는 순환 이웃을 사용하지 않는다. 예를 들어 8점 눈 윤곽의 눈꼬리에서
   올바른 양쪽 이웃 접선 [0,1] 대신 [0.707,0.707]이 나오는 사례를 실행 확인했다.
3. 중복점은 중심 차분 벡터가 0인 경우만 가중 1로 복귀한다. 어떤 점의 한쪽 이웃만
   중복되면 벡터가 0이 아닐 수 있으므로, '모든 중복점 제외'라는 설명은 부정확하다.
4. 곡선 그룹에 LaPa가 없어 해당 규약에는 접선 증폭이 적용되지 않는다. `refine_C_v7`의
   source 가중치는 WFLW .25 / LaPa .75다. 실험 설정에 따라 실제 적용 범위를 확인해야 한다.

신규 손실의 의도에 여러 선택지가 있어 이번에는 그 동작을 임의로 바꾸지 않았다.
